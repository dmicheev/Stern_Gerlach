# baseline-specs

## Why

Проект развивается без формальных спецификаций. Фиксируем текущее поведение
приложения как требования и сценарии, чтобы дальнейшая разработка шла по SDD:
каждое изменение начинается с proposal и spec-дельты поверх этого базового
набора, реализация сверяется со спекой, архивация мержит дельту в openspec/specs/.

## What

Добавляются шесть базовых спецификаций возможностей (capabilities):

- `cascade-simulation` — режим «Каскад»: дерево пучков, три физические модели,
  параметры аппаратов и источника, статистика, таймлайн и «классика-призрак»
- `bell-chsh-experiment` — режим «Белл»: схема со станциями и QRNG, две модели
  (синглет/локальный реализм), «дыры» η и V, живая статистика CHSH
- `physics-engine` — физическое ядро: единый интерфейс, эквивалентность
  WASM/TS-реализаций, Web Worker, модель поля, покрытие тестами
- `scene-visualization` — 3D-сцена: состав объектов, режимные камеры, учебные
  аннотации, взаимодействия, постобработка и стиль
- `screen-analysis-modal` — разбор экрана по клику: открытие, содержимое для
  каскада и Белла, объяснения «почему», поведение модалки
- `localization` — RU/EN: двуязычный UI, база «?»-подсказок, отсутствие
  жёстких строк

## How

Спеки описывают существующее поведение (as-is): формулировки проверены по
коду и ручным тестированием через браузер в текущей сессии разработки.
Формат — требования с критериями приёмки (WHEN/THEN). После валидации change
архивируется, дельты мержатся в основные спеки `openspec/specs/`.

## Impact

Только документация и процесс: код не меняется. Дальнейшие фичи оформляются
как отдельные changes поверх этих спек; правки поведения существующих
возможностей требуют модификации соответствующей спеки (MODIFIED/REMOVED
Requirements в дельте изменения).
